# Translations (French / Breton)

The interface is available in French and Breton (design D16). French is the reference: every
string exists in French, and a missing Breton string shows the French one instead.

Not translated, ever: what people write (interventions, names, schools, rejection messages),
the rejection quick-pick chips (fixed French text), and the exports (CSV and printable page are
always in French).

## Where the strings live

| File                       | Role                                                              |
| -------------------------- | ----------------------------------------------------------------- |
| `src/i18n/fr.ts`           | Reference dictionary. Every key must exist here.                  |
| `src/i18n/br.ts`           | Breton. Typed `Partial`: a missing key falls back to French.      |
| `src/i18n/br.reviewed.json`| The French text each Breton string was reviewed against (generated). |
| `src/i18n/core.ts`         | Plurals, times and dates (`Intl`), shared with the browser code.  |

Keys starting with `export.` are French-only (exports) and are not expected in `br.ts`.

## Adding or changing a string

1. Add the key to `fr.ts`, grouped with the screen it belongs to. Use `{name}` placeholders
   for values: `'mine.sentAt': 'Envoyée à {time}'`.
2. For a count, use a plural entry: `plural({ one: '{n} mot', other: '{n} mots' })`.
   Breton has five categories (`one`, `two`, `few`, `many`, `other`): 1 → one, 2 → two,
   3 and 9 → few, 20 → other. Give the Breton entry every form it needs; a missing form uses
   `other`.
3. Use it on the server with `tr.t('key', { … })` / `tr.tn('key', n)`. Browser modules get only
   the strings they need, listed where the page embeds them (`pickStrings(...)`); add the key
   there too.
4. Add the Breton text to `br.ts` if you know it; otherwise leave it out and it will show in
   French until a Breton speaker adds it.
5. Run `npm run i18n:check`: the new key shows as missing or "to review".

Changing the French text of an existing key marks its Breton translation as "to review",
since the Breton may no longer match.

## Breton review checklist

Before each AG (and before the rehearsal), a Breton speaker of the association reviews the
interface:

1. Run `npm run i18n:check`. It lists:
   - **Missing from br.ts**: keys with no Breton text (shown in French today);
   - **French changed or never reviewed**: Breton strings to check against their French;
   - **Unknown keys**: Breton keys that no longer exist in French (delete them).
2. Run `npm run i18n:check -- --checklist > review.md` to get every key as a table
   (French | Breton | note) the reviewer can tick, in a document or on paper.
3. For each line, check that the Breton:
   - says the same thing as the French, in the register used with members;
   - keeps every `{placeholder}` exactly as written (they are replaced by values);
   - for plural entries, has the right form for 1, 2, 3, 9 and 20 (dashboard counters);
   - fits: buttons and tabs must stay short on a phone.
4. Put the corrections in `br.ts`, then look at the main screens with the interface set to BR
   (participant page, listening page, Bureau login, dashboard, reject dialog, settings).
5. When everything is checked, run `npm run i18n:check -- --mark-reviewed` and commit
   `br.ts` and `br.reviewed.json` together. `npm run i18n:check` must then report no missing
   key and nothing to review.
